# Design — Ultimate Idle Frontline

สเปกเกมที่ตกลงแล้ว + สถาปัตยกรรม ทุกข้อเป็น `(SAID)` จนกว่าจะมีโค้ด · ตัวเลข balance ไม่อยู่ที่นี่ (อยู่ `src/shared/Config/`)
ขั้นตอนการทำอยู่ [plan.md](./plan.md)

**กติกาตัดสินใจ:** ตัวเลข/สูตร/balance/ของที่ไม่ใช่ gameplay → คิดเองได้ ปรับทีหลัง · อะไรที่ทำให้วิธีเล่นเปลี่ยน → ถามเจ้าของก่อน
**Asset ช่วงแรก:** โมเดล lobby effect icon ใช้แบบเรียบ ไม่มีสี (placeholder) ทั้งหมด

## 1. ภาพรวม

Idle RPG: ทีม hero เดินหน้าซ้าย→ขวา ตี monster/boss เองอัตโนมัติ ผู้เล่นแค่อัพเกรด · PC ก่อน มือถือทีหลัง · server ละ 6 คน
โมเดล 3D rig R6 · มุมกล้องหลัก 2D ปรับเป็น 3D ได้ (เรื่องของ client ล้วน)

## 2. ด่าน (Stage)

- 1 ด่าน level ไม่จำกัด · 1 level = 5 wave · wave สุดท้ายมี boss · ผ่านแล้วขึ้น level ถัดไป ยากขึ้นทุก level
- wave ซ้อนกันได้: wave ถัดไปมาตามจังหวะ "ความเร็วทีม" แม้ยังเคลียร์ wave ก่อนไม่หมด
  - ความเร็วทีม = ค่าความเร็วของ hero ที่เร็วที่สุดในแถวกลาง · ถ้าแถวกลางว่าง = ค่าเฉลี่ยของทุกตัวในทีม
- ปุ่ม **skip wave** (มีตั้งแต่เริ่มเกม): ปล่อยทั้ง 5 wave ออกมาพร้อมกัน · เปิด/ปิดค้าง มีผลจาก level ถัดไป · ใช้ได้เฉพาะ level ที่เคยผ่านแล้ว
- HP ทีมเต็มใหม่ทุกต้น level · ตัวที่ตายฟื้นเองหลัง 60 วิ ด้วย HP 50% หรือด้วยสกิลชุบ · ตายหมดพร้อมกัน = ทีมแตก
- **โหมด Progress (ค่าเริ่มต้น):** ทีมแตก → ถอย 1 level (ถอยซ้ำได้เรื่อยๆ) · ผ่าน → ขึ้นต่อเอง
- **โหมด Farm:** ปลดเมื่อเคยถึง level 200 · สลับแล้วลงไป level 1 ทันทีและวน loop
  - ระหว่างไต่ได้ gold/xp ปกติ (สมมติ) แต่ item/ของสวมใส่ไม่ drop ระหว่างทาง
  - ทีมแตกที่ level N → ได้ 1 ก้อน = item + ของสวมใส่ที่คำนวณจาก level 1..N-1 (รวม drop ปกติและของจากกล่อง) แล้วเริ่ม 1 ใหม่
  - ถึง level cap ของ rebirth นั้นโดยไม่ตาย = จบรอบ ได้ก้อน วนใหม่ (สมมติ)
  - สลับออกจาก Farm ระหว่างรอบ (ทีมยังไม่แตก) → รอบที่เล่นอยู่ทิ้ง ได้ก้อนของรอบ Farm ที่จบล่าสุดแทน
  - ก้อนคำนวณแบบรวม (จำนวนคาดหวังต่อชนิดแล้วสุ่มครั้งเดียว) ไม่สุ่มทีละ monster · เกินความจุ → auto-salvage

## 3. Hero และทีม

- เข้าเกมครั้งแรกเลือกตัวแรก 1 จาก warrior / mage / archer · ตัวอื่น (รวม healer) ซื้อด้วย gold · วิธีหา hero เพิ่มค่อยคิด
- ทีมเริ่ม 1 ตัว ปลดเพิ่มจาก skill tree สูงสุด 4
- hero มี level, สกิล (ใช้อัตโนมัติ), การเปลี่ยนอาชีพของตัวเอง · เปลี่ยนอาชีพแล้ว max cap ของสวมใส่เพิ่ม
- XP hero หารตามจำนวนตัวที่ลงสนาม · level ส่วนตัวคิด XP แยกสูตร
- แถว หน้า/กลาง/หลัง ลงได้แถวละสูงสุด 4 · หน้ารับดาเมจก่อน · กลาง = ฐานความเร็วทีม · หลังไม่โดนตีจนกว่าหน้า+กลางล้มหมด
- แต่ละ class มีตำแหน่งที่เหมาะและคู่ที่เข้ากัน (โบนัส — ตัวเลขคิดเอง)

## 4. ของ

- ช่องสวมใส่ 10: อาวุธหลัก · อาวุธรอง · หมวก · เกราะ · กางเกง · รองเท้า · กำไล ×2 · แหวน ×2
- ไม่ผูก class แต่ใส่ไม่ตรง class → stat ลด + ความสามารถอาวุธใช้ไม่ได้ (ของทุกชิ้นมีป้าย class)
- tier: common · uncommon · rare (เริ่มแค่นี้) · มี gear score สุ่ม และ max gear score ต่อ tier
- ของสวมใส่และ item ทุกชิ้นมี **tier · level · rebirth** (บางชิ้นหาได้เฉพาะ rebirth นั้น)
- level ของที่ drop = level ด่าน แต่ไม่เกิน cap ของ rebirth ที่กำลังเล่น (cap 100 เล่นด่าน 200 ก็ได้ของ level 100) · ทุกด่านมีโอกาส drop ทุก tier ที่ด่านนั้นมี แล้วแต่ดวง
- สวมใส่ได้เมื่อ level hero ตัวที่ใส่ ≥ level ของ (ของ 75 กับ hero 50 ใส่ไม่ได้)
- **Tag:** item และของสวมใส่ทุกชิ้นมี tag (กำหนดใน Config + สร้างอัตโนมัติจาก tier/ช่อง/class/rebirth) · ช่องค้นหาพิมพ์ `@tag` เพื่อกรอง พิมพ์ข้อความธรรมดาเพื่อหาชื่อ
- auto-salvage: ย่อยแล้วได้ gold + วัตถุดิบตีบวก · ตั้งกรองตาม tier ได้
- ความจุ 500 ชิ้น (ไม่นับที่สวมอยู่ — สมมติ)
- monster/boss ตาย drop: gold, xp, item, ของสวมใส่, กล่อง
- **กล่อง:** ธรรมดา (monster) / boss · stack สูงสุด 25 อัพความจุได้ · เต็มแล้ว drop หาย · เปิดได้ของ gear score ดีกว่า + ของที่ drop ปกติไม่มี
  - กล่องแยก stack ตาม ชนิด + rebirth ที่ได้มา + ช่วง level 25 (1–25, 26–50, …) · ของในกล่องสุ่ม level ในช่วงนั้น และเป็นของ rebirth ของกล่อง
  - 5 กล่อง (ธรรมดาหรือ boss, stack เดียวกัน) → 1 กล่องตรง class ช่วงเดียวกัน · ถือได้สูงสุด 10 ต่อ stack · เลือก class และจำนวนที่จะเปิดตอนกดเปิด
  - เปิดได้ 3 แบบ: เปิดเอง · เปิดทั้งหมด · เปิดอัตโนมัติ (ปลด/อัพจาก skill tree มี cooldown ต่อรอบ)

## 5. เสริมพลัง

- **ตีบวก:** +1..+10 · ค่าพลังต่อขั้นคงที่ · ติด/ไม่ติดเท่านั้น ไม่แตก · ไม่ติดเสีย gold + ของที่ใช้ · บางชิ้นต้องมี item เฉพาะร่วมด้วย
- **ช่องเสริม:** ของชิ้นเดียวกัน + tier เดียวกัน (ไม่สน gear score) รวมกัน: 0+0 → 1 ช่อง · k+k → k+1 · สูงสุด 5 · มี item หายากข้ามขั้นได้ทันที
  - แต่ละช่องเลือกชนิด Gem / Artifact / Relic และเปลี่ยนไปมาได้หลังเปิด
  - ชนิด: Gem = stat ตรงๆ · Artifact = ผลพิเศษตอนสู้ (ดูดเลือด ตีกระจาย ฯลฯ) · Relic = โบนัสทั้งทีม/เศรษฐกิจ (gold% xp% อัตรา drop)
  - ถอดของออกจากช่องได้ เสีย gold ของไม่หาย · เปลี่ยนชนิดช่อง → ของข้างในคืนกระเป๋า
  - รวมของ: ชิ้นหลักเก็บทุกอย่าง (บวก, gear score, enchant) · ชิ้นวัตถุดิบหายไป
- **Enchant:** ใช้ item หายากสุ่ม trait ให้ของสวมใส่ เช่น ตีเร็ว +10, ตีแรง +10, วิ่งเร็ว +10 · 1–3 บรรทัดตาม tier สุ่มใหม่ทั้งหมดทุกครั้ง (สมมติ)

## 6. ระบบอื่น

- **Skill tree:** ต้นเดียวทั้งบัญชี 3 สาย (ต่อสู้ · เศรษฐกิจ · ระบบ) เป็นเส้นแยกสายเห็นชัด · ไม่มีแต้มจำกัด ส่วนใหญ่อัพด้วย gold (บางอันใช้ item / แต้ม rebirth) · reset ไม่ได้ · node ประเภทความสามารถติดตัว/ใช้งาน เปิด-ปิดได้ · ซื้อครบทุก node ได้ในที่สุด (สมมติ)
  - ปลดช่องทีม · % offline · ความจุกล่อง · เปิดกล่องอัตโนมัติ ฯลฯ
- **Level ส่วนตัว:** ปลดฟีเจอร์ตามขั้น (Farm, trade, ฯลฯ) + โบนัสเล็กน้อยทั้งบัญชี
- **สกิล hero:** ติดตัว 1 + ใช้เอง 2 (cooldown) ปลดตาม level hero · แรงขึ้นเมื่อเปลี่ยนอาชีพ
- **เปลี่ยนอาชีพ:** เส้นตรง 2 ขั้นต่อ class · ใช้ level hero + gold + item (สายแยกค่อยเพิ่ม)
- **เงินตรา:** Gold · Ruby (ได้จาก battle pass และ quest) · Robux
- **Quest:** รายวัน · รายอาทิตย์ · รายเดือน · ให้ Ruby (เนื้อหา quest คิดเอง)
- **Battle pass:** สายฟรี + สายพรีเมียม (Robux) · ฤดูละ 1 เดือน ตรงกับรอบร้านรายเดือน · แต้ม pass จาก quest · ให้ Ruby และของ
- **Rebirth:** ไม่ reset อะไร · เพิ่ม max cap (level item ที่ drop, level สวมใส่, level hero, level ส่วนตัว ฯลฯ) + ของเล็กน้อย + ความยากทุกด่านเพิ่ม · เงื่อนไข = ผ่าน level ที่กำหนด
  - หน้าตาด่าน/monster ไม่เปลี่ยนตาม rebirth
  - เลือกเล่น rebirth ที่ต่ำกว่าที่ปลดแล้วได้ (เช่นปลด 5 กลับไปเล่น 1 เพื่อหาของเฉพาะ rebirth 1) · ความยาก, cap และตาราง drop ใช้ของ rebirth ที่เลือกเล่น
  - level ด่านเก็บแยกต่อ rebirth (สมมติ) · rebirth ใหม่แล้ว level ปัจจุบันคงเดิม ถ้าไม่ผ่านก็ถอยเองตามโหมด Progress
- **Offline:** ได้เฉพาะ gold + xp · 20% ของอัตราออนไลน์ (เพิ่มได้จาก skill tree) · สะสมไม่จำกัดเวลา
- **AFK:** ไม่ขยับ 19:30 นาที → rejoin อัตโนมัติ (teleport กลับ place เดิม)
- **Trade:** ทุกอย่าง trade ได้ไปก่อน รวม gold · เฉพาะคนใน server เดียวกัน · ไม่มีค่าธรรมเนียม · ของที่สวมอยู่ต้องถอดก่อน · ต้องถึง level ส่วนตัวที่กำหนดก่อน (กันไอดีรอง)
- **Gamepass:** x2 gold · x2 xp (มีผลกับรายได้ offline ด้วย) · gift ให้คนใน server เดียวกันเท่านั้น (developer product ให้สิทธิ์ผ่าน save ผู้รับ)
- **ร้านจำกัดรายเดือน:** ขายด้วย Robux / gold / Ruby
- **ดูด่านคนอื่น:** เห็นเป็น 2D · คลิกเพื่อปรับมุมได้ · QoL ทำท้ายๆ
- **ตัวเลข:** แสดงแบบ suffix (K M B T Qa Qi Sx Sp Oc No Dc …) · เก็บเป็น number ปกติ กันไม่ให้ถึง inf/NaN
- **ทำทีหลังสุด:** raid / challenge / event / boss map · tutorial · ตั้งค่า · leaderboard · รางวัลรายวัน · โค้ด

## 7. สถาปัตยกรรม

| เรื่อง | แนวทาง |
|---|---|
| การต่อสู้ | server จำลองเป็นตัวเลขล้วน (ไม่มี Instance/Humanoid) คำนวณทั้ง level ล่วงหน้าด้วย seed → ส่ง timeline ให้ client เล่นภาพ → ให้รางวัลเมื่อถึงเวลาจบ |
| อัพเกรดกลาง level | มีผลตอนเริ่ม level ถัดไป |
| ภาพ | client สร้างโมเดลเอง ใช้ pool จำกัดจำนวนบนจอ |
| ข้อมูลผู้เล่น | โหลด profile ครั้งเดียว ทุกระบบอ่านจาก memory |
| Replication | snapshot ตอนเข้า แล้วส่งเฉพาะ delta รวมชุด |
| ค่าพลัง hero | cache · คำนวณใหม่เมื่อ dirty เท่านั้น |
| ตัวเลขเกม | `src/shared/Config/` · อัตราสุ่ม (drop/ตีบวก/enchant) อยู่ `src/server/Secret/` |
| เจ้าของ state | 1 ระบบเป็นเจ้าของ 1 ก้อน ระบบอื่นแก้ผ่าน API ของเจ้าของ (เงิน → Currency, ของ → Inventory) |

### โฟลเดอร์ (เป้าหมาย)

```
src/shared/   Net.luau · Types.luau · Format.luau · Config/ · Formula/ · Text/
src/server/   Data/ · Util/ (RateLimit, Guard, Rng) · Secret/ · Systems/
              Systems: Replication Currency Inventory Stage Hero SkillTree Rebirth Box Enhance Socket Enchant Trade Shop Quest BattlePass Offline
src/client/   State/ · Battle/ (timeline, pool, กล้อง) · UI/ (Core/ + โฟลเดอร์ต่อหน้า)
```

### Save

- ของสวมใส่ต่อชิ้น: `uid, baseId, tier, level, rebirth, gearScore, plus, sockets[], enchants[]` — คำอธิบาย/stat ฐานอยู่ Config
- ของ stack ได้: `id → จำนวน` · `uid` ออกโดย server ไม่ซ้ำ (ตรวจ dupe + log trade)
- มี `SchemaVersion` + migrate ตั้งแต่แรก · ห้ามใส่ inf/NaN ลง save

### ความปลอดภัย

- client ส่งแค่เจตนา · server ตรวจ ชนิด/ช่วงค่า/ความเป็นเจ้าของ/เงื่อนไข แล้วสุ่มและตัดสินเอง
- rate limit ทุก remote · ธุรกรรม = ตรวจครบก่อน แล้วหัก+ให้โดยไม่มี yield คั่น
- Trade: สอง profile ใน server เดียวกัน · ล็อกของ · ยืนยัน 2 ชั้น · สลับจังหวะเดียว · log
- Robux: `ProcessReceipt` กันซ้ำด้วย purchaseId ใน profile

### ทรัพยากร

- server ไม่มี loop ต่อเฟรม · เซฟตามรอบ ProfileStore · delta รวมชุดต่อ level
- client: pool โมเดล/VFX · inventory เป็น virtual list · Config frozen อ้างด้วย id

## 8. ตัวละครผู้เล่นและ lobby

- มี avatar เดินได้ใน lobby กลาง (placeholder เรียบ) · ด่านของผู้เล่น 6 ช่องวางรอบ/ติด lobby เดินไปดูของคนอื่นได้
- กล้อง 2 โหมด: เดิน (กล้อง Roblox ปกติ) / ดูด่าน (กล้องจับด่าน 2D ปรับ 3D ได้) สลับด้วยปุ่มบน HUD (สมมติ) · เข้าเกมมาเริ่มที่โหมดดูด่านของตัวเอง (สมมติ)
- เกมเดินต่อเองไม่ว่าจะอยู่โหมดไหน · avatar ไม่มีผลต่อการต่อสู้

- ข้อความในเกม: ภาษาอังกฤษเท่านั้นไปก่อน (`src/shared/Text/`)

## 9. คำถามค้าง

- Gamepass จะมีอะไรบ้างนอกจาก x2 gold / x2 xp — เจ้าของจะกำหนดทีหลัง
