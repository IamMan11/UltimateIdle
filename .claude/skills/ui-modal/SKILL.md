# UI Modal — มาตรฐานทั่วไป

ไฟล์นี้ = หลักการที่ใช้กันจริงทุกแพลตฟอร์ม · `references/roblox-react.md` = วิธีเขียนใน Roblox + React-lua (อ่านต่อเมื่อจะแตะโค้ด UI ฝั่ง client) · ถ้าโปรเจกต์มี UI convention ของตัวเองใน `CLAUDE.md` ให้ยึดอันนั้น

## 1. ใช้ modal เมื่อไหร่ (และเมื่อไหร่ไม่ควร)

ใช้ modal เฉพาะเมื่อ **ต้องหยุดผู้ใช้** เพื่อ:
- ขอการตัดสินใจก่อนไปต่อ (ยืนยัน/เลือก)
- ป้องกันการเสียข้อมูล/ของ (ลบ ขาย รีเซ็ต ออกโดยไม่เซฟ)
- โฟกัสงานสั้น ๆ ที่ต้องทำให้จบ (กรอกชื่อ เลือก 1 จาก N)

**ห้าม**ใช้ modal เมื่อ: แค่แจ้งผล (ใช้ toast) · เนื้อหายาวหรือซับซ้อน (ใช้หน้าเต็ม) · ซ้อน modal บน modal · โฆษณา/ขัดจังหวะโดยผู้ใช้ไม่ได้ขอ · แทนที่หน้าทั้งหน้า

กฎนิ้วโป้ง: "ถ้าผู้ใช้ไม่ตอบแล้วเกม/แอปไปต่อไม่ได้ → modal · ถ้าไปต่อได้ → ไม่ใช่ modal"

## 2. ชนิด (ตาม Carbon Design System)

| ชนิด | ลักษณะ | ปุ่ม | ปิดด้วย |
|---|---|---|---|
| **Passive** | แจ้งข้อมูล ไม่ต้องทำอะไร | ไม่มี / "ปิด" | X · Esc · คลิกนอกกรอบ |
| **Acknowledgment** | ต้องรับทราบ | 1 ปุ่ม | ปุ่ม · X · Esc |
| **Transactional** | ต้องตัดสินใจ | ยกเลิก + หลัก | ปุ่ม · X · Esc (**ไม่**คลิกนอกกรอบ) |
| **Transactional-danger** | การกระทำย้อนกลับไม่ได้ | ยกเลิก + ปุ่มอันตราย | ปุ่มเท่านั้น + Esc = ยกเลิก |
| **Progress** | หลายขั้น | ยกเลิก · ย้อน · ถัดไป | ปุ่ม · Esc = ยกเลิกทั้งหมด (ถามก่อนถ้ากรอกไปแล้ว) |
| **Non-modal / Toast** | ไม่บล็อก | — | เอง (timer) หรือ X |

## 3. โครงสร้าง + anatomy

```
Backdrop   เต็มจอ หรี่ 35–60% · กินคลิก · ทำให้ข้างล่าง inert
└── Dialog  กึ่งกลาง (desktop) / bottom-sheet (mobile) · กว้างสูงสุด ~560px / 90vw
    ├── Title      สั้น เป็นคำถามหรือกริยา: "ลบคลาสนี้?" ไม่ใช่ "คำเตือน"
    ├── Close (X)  มุมบนขวา — ต้องมองเห็นเสมอ (ยกเว้น modal บังคับเลือก)
    ├── Body       ≤ 2–3 ประโยค · บอก *อะไร* จะเกิด *กับอะไร* *ย้อนได้ไหม*
    └── Footer     ปุ่มเรียงขวา · [ยกเลิก] [ปุ่มหลัก]
```

- ขนาดคงที่ตามเนื้อหา ไม่ยืดตามจอ · ถ้าต้อง scroll ภายใน = เนื้อหาเยอะไป พิจารณาหน้าเต็ม
- 1 modal = 1 งาน · ไม่มีแท็บ/ตารางใหญ่/ฟอร์มยาวใน modal
- ซ้อนได้สูงสุด 1 ชั้น (modal → confirm) และชั้นที่สองต้องเล็กกว่า

## 4. ปุ่ม — ลำดับ ป้าย สี

- **ลำดับคงที่ทั้งแอป**: ยกเลิก/รองซ้าย · หลักขวาสุด (เว็บ/Material/Carbon/Windows ใช้แบบนี้; เกม console ใช้ตำแหน่งเดียวกันทุกหน้า) · ห้ามสลับไปมา
- **ป้ายเป็นกริยาเฉพาะ**: "ลบ" "ขาย 3 ชิ้น" "รีเซ็ตสกิล" — ไม่ใช่ "ตกลง"/"ใช่"/"OK" · ปุ่มรองคือ "ยกเลิก" ไม่ใช่ "ไม่"
- สีอันตราย (แดง) เฉพาะ action ที่ย้อนไม่ได้ · ปุ่มหลักปกติใช้สีเน้นของธีม · ยกเลิกไม่มีสี
- ปุ่มหลัก 1 ปุ่มเท่านั้น · ≤ 3 ปุ่มต่อ modal
- **ค่า default (Enter / A)**:
  - ปกติ → ปุ่มหลัก
  - อันตราย/ย้อนไม่ได้ → **ยกเลิก** (กด Enter รัว ๆ ต้องไม่ลบของ)
- Hit target ≥ 44×44pt (touch) / 48×48px @1080p (เกม) · ช่องว่างระหว่างปุ่ม ≥ 8px

## 5. การยืนยัน action อันตราย

- ข้อความต้องระบุ **สิ่งที่จะหาย + ผลลัพธ์ + ย้อนได้ไหม**: "ขาย Flame Sword [Epic] ได้ 120 coin — ของจะหายถาวร" ไม่ใช่ "การกระทำนี้ไม่สามารถย้อนกลับได้"
- ยิ่งแพง ยิ่งเพิ่มแรงเสียดทาน: ปุ่มธรรมดา → กดค้าง (hold 0.6–1.0s) → พิมพ์คำยืนยัน (เฉพาะบัญชี/เซฟทั้งก้อน)
- ปุ่มอันตรายต้องไม่อยู่ตำแหน่งเดียวกับปุ่ม "ยืนยัน" ของ modal ก่อนหน้า (กันกดทะลุ) — ดีเลย์รับ input 300–500ms หลังเปิด
- ให้ **undo** ได้ถ้าทำได้ (toast "ขายแล้ว · เลิกทำ" 5s) ดีกว่าถามยืนยันทุกครั้ง
- Esc / B / คลิกนอกกรอบ = **ยกเลิกเสมอ** ห้ามเป็นการยืนยัน
- ปิดแล้วต้องมี feedback: toast/ข้อความบอกว่าทำอะไรไปแล้ว

## 6. Focus & keyboard (WAI-ARIA Dialog Pattern)

- เปิด: focus **เข้า** modal ทันที
  - ข้อมูล/ต่อเนื่อง → ปุ่มที่ใช้บ่อยสุด
  - อันตราย → ปุ่มที่ปลอดภัยสุด (ยกเลิก) หรือข้อความเตือน
  - เนื้อหายาว → หัวข้อ (กันเลื่อนข้ามต้นเรื่อง)
- `Tab` / `Shift+Tab` วนอยู่ **ภายใน** modal (focus trap) · ข้างล่างต้อง inert (ไม่รับคลิก/คีย์/scroll)
- `Esc` ปิด (= ยกเลิก)
- ปิดแล้ว focus **กลับไปที่ตัวที่เปิด** (ถ้าหายไปแล้ว → จุดถัดไปที่สมเหตุสมผล)
- เว็บ: `role="dialog"` `aria-modal="true"` `aria-labelledby=<title>` (+ `aria-describedby` ถ้าเนื้อหาสั้น) · ใช้ `<dialog>.showModal()` หรือ `inert` บน root
- ปิดแล้ว **unmount จริง** (ไม่ใช่ซ่อน) เพื่อปลด listener/timer ทั้งหมด

## 7. Gamepad / console (เกม)

- เปิดแล้วตั้ง selection ไปที่ปุ่ม default ของข้อ 4 ทันที · ปิดแล้วคืน selection ให้ตัวที่เปิด
- selection วนอยู่ในกรอบ ห้ามหลุดไปปุ่มหน้าข้างล่าง
- `A/✕` = ปุ่มที่ focus · `B/○` = ยกเลิก/ปิด (เท่ากับ Esc) · รองรับสลับ ○=ยืนยัน (ญี่ปุ่น) เป็น setting
- แสดง button prompt ตามอุปกรณ์ล่าสุด (เปลี่ยนหลัง 200ms กันกะพริบ) ใช้ชื่อ action ไม่ hardcode "กด A"
- ขณะ modal เปิด: **กลืน input เกม** (เดิน/สกิล/ยิง) · ถ้าเกมมี mouse-lock ต้องปล่อยเมาส์ (Roblox: `Modal=true` ที่ backdrop)
- ถ้าเป็นเกมผู้เล่นเดียวให้ pause ได้ · multiplayer ห้าม pause → ทำ modal ให้สั้นและปิดง่าย

## 8. Motion

- เข้า 200–300ms ease-out (`cubic-bezier(0,0,0.2,1)`): backdrop fade + กรอบ scale 0.95→1.0 หรือเลื่อนขึ้น 8–16px
- ออก 150–200ms ease-in · เร็วกว่าเข้าเสมอ
- Animate เฉพาะ transform + opacity · ไม่ animate ขนาด/ตำแหน่ง layout
- ห้ามบล็อก input ระหว่าง animation ปิด · กดซ้ำได้ทันที
- Reduced-motion: เหลือ fade 150ms
- Toast: เข้า 200ms · ค้าง 3–5s · ออก 300ms · แสดงพร้อมกัน ≤ 2–3 · รวมรายการชนิดเดียวกัน ("Gold +80 ×5")

## 9. Layer / z-index

ลำดับคงที่ทั้งแอป: dropdown < modal < tooltip < toast/notification < dev overlay (ตัวอย่าง 100 / 200 / 300 / 400) · เลขเกิน 1000 = สัญญาณว่าโครงสร้างพัง · modal ทุกตัว mount ที่ root ชั้นเดียวกัน (portal) ไม่ฝังในหน้าย่อย

## 10. State ownership

- "เปิดอยู่ไหม + ข้อมูลอะไร" อยู่ใน state กลางตัวเดียว (store/reducer) ไม่ใช่ state ในคอมโพเนนต์ · เปิด = ใส่ข้อมูล, ปิด = `nil`
- modal ที่มีผลต่อข้อมูลจริง (ซื้อ/ลบ/เซฟ): ปุ่มหลักส่ง request → รอผล → ค่อยปิด/แจ้ง · ปุ่ม disabled + spinner ระหว่างรอ · ห้ามเดาว่าสำเร็จ
- เปลี่ยนหน้า/จบเกม/ตัดการเชื่อมต่อ → เคลียร์ modal ค้างทุกตัว

## 11. Anti-patterns (เจอแล้วต้องแก้)

- "OK/Cancel" บน action ที่ย้อนไม่ได้ · ปุ่มอันตรายเป็น default · Esc = ยืนยัน
- modal แจ้งข้อมูลที่ไม่ต้องตัดสินใจ (ควรเป็น toast)
- ปิดด้วยการคลิกนอกกรอบบน modal ที่มีฟอร์มกรอกอยู่
- modal ซ้อน modal ซ้อน modal
- ไม่มีปุ่มปิดที่มองเห็น · focus ไม่เข้า/ไม่กลับ · ข้างล่างยังกดได้
- สลับตำแหน่งปุ่มระหว่างหน้า · ป้ายเป็นคำถามซ้อน ("ไม่ยกเลิกใช่ไหม?")
- ขนาดยืดตามจอจน text แตก · เนื้อหาต้อง scroll
- ใช้ `Visible=false` แทน unmount แล้ว listener ค้าง
- animation > 300ms หรือเด้ง bounce บน modal ที่เปิดบ่อย

## 12. Checklist

- [ ] จำเป็นต้องหยุดผู้ใช้จริง (ไม่ใช่ toast / หน้าเต็ม)
- [ ] ชนิดถูก (ข้อ 2) และนโยบายการปิดตรงกับชนิด
- [ ] Title เป็นคำถาม/กริยา · body บอกผล + ย้อนได้ไหม ≤ 3 ประโยค
- [ ] ปุ่ม: ยกเลิกซ้าย หลักขวา · ป้ายกริยาเฉพาะ · 1 ปุ่มหลัก · ≤ 3 ปุ่ม
- [ ] default = ปลอดภัยสำหรับ action อันตราย · ดีเลย์รับ input 300–500ms
- [ ] Esc / B / X ปิด = ยกเลิก · focus เข้า-วน-กลับ · ข้างล่าง inert
- [ ] Gamepad ไปถึงทุกปุ่ม · prompt ตามอุปกรณ์ · กลืน input เกม · ปล่อย mouse-lock
- [ ] Hit target ≥ 48px · ช่องว่าง ≥ 8px · text ≥ 14px @1080p
- [ ] เข้า 200–300ms / ออก 150–200ms · transform+opacity เท่านั้น · reduced-motion
- [ ] z-index ตามสเกลกลาง · mount ที่ root
- [ ] state อยู่ใน store กลาง · ปิด = nil · unmount จริง · เคลียร์เมื่อเปลี่ยนหน้า
- [ ] action จริงรอผล server ก่อนปิด · มี feedback หลังทำ
- [ ] ทดสอบ: เมาส์ · คีย์บอร์ดล้วน · gamepad ล้วน · touch · จอเล็กสุดที่รองรับ
